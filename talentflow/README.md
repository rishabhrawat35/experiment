# TalentFlow

Hiring-funnel analysis of Acme's Airtable ATS ("TalentFlow" base): answers two VP
questions about hiring channels and offer acceptance, plus a data-quality audit,
using a raw Airtable JSON pull as the only input. Every number is reproducible from
that pull with the commands below — no manual steps, no hidden state.

## Reproduce everything, from scratch

```bash
# 1. Pull raw data from Airtable (needs .env with AIRTABLE_TOKEN, AIRTABLE_BASE_ID; requires jq)
./fetch_data.sh                        # writes data/*.json

# 2. Build every analysis view
cd analysis
python3 build_all_views.py             # writes analysis/output/*.csv

# 3. Independently re-verify the headline numbers (different engine: sqlite3, not the
#    dict/list aggregation build_all_views.py uses)
python3 challenge_all_views.py         # should print N/N PASS, exits non-zero on any FAIL

# 4. Bundle the CSVs for the dashboard
python3 build_dashboard_data.py        # writes analysis/dashboard_data.json
cd ..

# 5. Open the dashboard
open artifacts/talentflow-analysis-dashboard.html   # reads ../analysis/dashboard_data.json via fetch()
```

Step 5 needs its own directory served over HTTP (not `file://`) for the `fetch()` to
work, e.g. `python3 -m http.server` from the repo root, then browse to
`/artifacts/talentflow-analysis-dashboard.html`.

Optional: `python3 build_viewer_data.py` (repo root) builds `viewer_data.json`, a
flattened, link-resolved dump of all 8 raw tables consumed by
`artifacts/talentflow-data-browser.html` — a raw-record browser, independent of the
analysis pipeline above. Not required for the dashboard or findings.

`.env` holds the Airtable credentials (`AIRTABLE_TOKEN`, `AIRTABLE_BASE_ID`) used
only by `fetch_data.sh`. Treat it as a secret: never share this folder or commit it
without stripping or rotating those values first.

## What's here

```
data/                   raw Airtable JSON pull (one file per table) — the only true input
analysis/
  common.py             shared loaders + the phone-based duplicate-candidate matcher
  build_all_views.py    main pipeline: reads data/*.json, writes analysis/output/*.csv
  challenge_all_views.py  re-derives the headline numbers via sqlite3, asserts they match
  build_dashboard_data.py  bundles analysis/output/*.csv into dashboard_data.json
  output/               generated CSVs (one per view) — do not hand-edit, rerun the pipeline
  dashboard_data.json   generated bundle consumed by the dashboard HTML
artifacts/
  talentflow-analysis-dashboard.html   the VP-facing dashboard (Q1/Q2 answers + data-quality summary)
  talentflow-data-browser.html         raw-record viewer over viewer_data.json
docs/
  talentflow-data-quality-audit.md     full data-quality write-up
  talentflow-q3-roadmap.md             roadmap informed by the analysis
findings.md             every quantitative claim used anywhere in this project, with its
                         source file and a confidence label
session-transcript.jsonl  Claude Code session log for this exercise (raw JSONL)
PROCESS.md              readable summary of the session: prompt timeline, direction changes, decisions
fetch_data.sh           pulls Departments/People/Job Openings/Candidates/Applications/
                         Interviews/Offers/Findings from Airtable into data/*.json
build_viewer_data.py    builds viewer_data.json for the raw data browser (optional, separate
                         from the analysis pipeline)
viewer_data.json        generated by build_viewer_data.py
```

Everything under `analysis/output/`, `analysis/dashboard_data.json`, and
`viewer_data.json` is generated — safe to delete and regenerate at any time.
